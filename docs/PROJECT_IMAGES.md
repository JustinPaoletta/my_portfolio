# Project images

Keep original artwork in `assets/source/`. Production assets belong in `public/images/projects/`.
The portfolio build serves `public/`; it does not copy the source-artwork directory.

## Logo pipeline

Run from the repository root:

```sh
npx --yes npm@11.6.4 ci
npm run optimize:project-logos
```

`scripts/optimize-project-logos.mjs` resolves paths relative to its own file.
It uses the pinned Sharp dependency with Lanczos3 resizing and never enlarges the source.
It does not crop, recolor, or flatten artwork.

| Source master           | Generated prefix    | Widths                                 | Encoding                               |
| ----------------------- | ------------------- | -------------------------------------- | -------------------------------------- |
| `sidequest-sq-logo.png` | `sidequest-sq-logo` | 60, 120, 180, 240, 480, 720, 960, 1254 | WebP quality 90, effort 6              |
| `wae-exports-logo.png`  | `wae-exports-logo`  | 60, 120, 180                           | Lossless WebP, `exact: true`, effort 6 |
| `plexarr_icon.png`      | `plexarr-icon`      | 60, 120, 180                           | Lossless WebP, `exact: true`, effort 6 |

The script writes fourteen configured variants. It checks format, dimensions, and alpha-channel presence.
For the six lossless variants, it compares decoded pixels with the resized source before writing.
SideQuest and Wild Apricot keep opaque backgrounds. Plexarr keeps transparency.
Lossy SideQuest WebPs are not byte-identical or pixel-identical copies of the PNG.

The old `sidequest-logo.png` skyline artwork remains preserved as historical source.
Its earlier public variants are not regenerated by the current script.

## Demo media

`scripts/optimize-project-demos.mjs` creates responsive project captures from preserved source files.
Run:

```sh
npm run optimize:project-demos
```

The source README and capture manifest are the maintained source for revisions, dimensions, workflows, fixture boundaries, and hashes.
See [project capture notes](../assets/source/project-demos/README.md).
Do not label a screenshot as an interactive application, a fixture as live data, or viewport emulation as physical-device acceptance.

Keep new media filenames distinct when the capture changes, so old cached content does not mask the update.
Retain source artwork and useful acceptance records before removing generated review output.

## Browser checks

The Projects components own `srcset`, `sizes`, display dimensions, alternative text, and media controls.
Keep these declarations aligned with generated widths and actual layout.

At mobile and desktop widths:

1. Inspect `currentSrc`, painted dimensions, and `devicePixelRatio`.
2. Confirm the selected variant is appropriate for its rendered size.
3. Confirm PNG source masters are not requested by the portfolio.
4. Inspect transparent edges against light and dark cards.
5. Check keyboard controls, captions, and transcript alternatives for media.
6. Check that inactive gallery views and opt-in recordings stay unloaded until needed.

Use the existing `project-images` and `project-showcases` browser suites for regressions.
Inspect changed images before updating approved visual baselines.

Favicons and Open Graph artwork use the separate [branding pipeline](../assets/branding/README.md).
